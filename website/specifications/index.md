# Specifications

The repository keeps its normative rules in the source tree under `docs/specs/`.

## What belongs here

- object format and identity rules
- storage and backend contract expectations
- linker and compatibility guarantees
- versioning and release rules
- viewer and security requirements

## Recommended reading order

1. [AGENTS.md](https://github.com/dmundt/go-cask/blob/main/AGENTS.md)
2. [docs/index.md](https://github.com/dmundt/go-cask/blob/main/docs/index.md)
3. [docs/specs/AGENT.md](https://github.com/dmundt/go-cask/blob/main/docs/specs/AGENT.md)
4. [docs/specs/cas-core.md](https://github.com/dmundt/go-cask/blob/main/docs/specs/cas-core.md)

## Why the website should host a summary

The repository specs are authoritative, but a documentation site makes the project easier to navigate for new users. Developers should be able to read a short architecture summary and then jump into the exact specification they need.
