# Specifications

The repository keeps its normative rules under `docs/specs/`. Those files define the architecture and implementation contracts that the project depends on.

## Start here

1. [AGENTS.md](https://github.com/dmundt/go-cask/blob/main/AGENTS.md)
2. [docs/index.md](https://github.com/dmundt/go-cask/blob/main/docs/index.md)
3. [docs/specs/AGENT.md](https://github.com/dmundt/go-cask/blob/main/docs/specs/AGENT.md)
4. [docs/specs/cas-core.md](https://github.com/dmundt/go-cask/blob/main/docs/specs/cas-core.md)

## What you will find

- object format and identity rules
- storage and backend contract expectations
- compatibility and migration guarantees
- versioning and release design
- viewer and security requirements

## Why the website also includes a summary

The repository specs are authoritative, but the website makes the project easier to navigate for new users. Developers should be able to read a short architecture summary and then jump directly to the specification they need.
